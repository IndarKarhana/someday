# Someday

A small, native iPhone app for the occasional extraordinary day. Working title: **Someday**.

SwiftUI · iOS 17+ · WidgetKit · completely on-device · no third-party dependencies.

## Experience

- Original pixel artwork, warm paper-colored screens, black keepsakes, and a restrained lime accent.
- One fixed daily result. Reopening never rerolls a date.
- Today screen, a chronological collection, full-screen keepsakes, and PNG sharing.
- Small and medium Home Screen widgets; circular, rectangular, and inline Lock Screen widgets.
- Optional local win notifications; no remote push service.
- Encrypted, same-device collection receipts plus portable PNG keepsakes. No transferable win identities.
- System fonts, VoiceOver labels, scrollable layouts, enlarged headline text, and reduced-motion support.

## Open on an iPhone

1. Install full Xcode and its iOS platform support. Command Line Tools alone cannot build an iPhone app.
2. Open `Someday.xcodeproj` and choose the **Someday** scheme.
3. In `Config/App.xcconfig`, change `SOMEDAY_BUNDLE_ID` from `com.example.someday` to your unique identifier. The widget, App Group, and shared Keychain access-group IDs derive from it.
4. In Signing & Capabilities, select your development team for **both** Someday and SomedayWidget. Register/enable the same App Group, `group.<your bundle ID>`, on both targets. Enable Keychain Sharing on both targets with the same `$(AppIdentifierPrefix)<your bundle ID>.security` access group. Provisioning profiles must support both capabilities on a physical device.
5. Select an iPhone simulator or connected iPhone and Run. Start your story, then add the widget using the in-app guide.

For a simulator build after full Xcode is installed:

```sh
xcodebuild -project Someday.xcodeproj -scheme Someday \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath .build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

No account, API key, backend, package installation, or paid third-party service is needed by the app.

## Daily odds

| Number | Daily probability | Average interval |
| --- | --- | --- |
| 5 | 1 / 60 | 60 days |
| 4 | 1 / 365 | About a year |
| 3 | 1 / 1,825 | About five years |
| 2 | 1 / 7,300 | About twenty years |
| 1 | 1 / 36,500 | About a hundred years |

There is at most one win per day. The overall probability of a win is 4,406 / 219,000, approximately 2.012%. An average interval is not a promise or a deadline. The UI explains this.

## How it stays small and consistent

An OS-generated 256-bit installation key and an ISO calendar date feed HMAC-SHA256. Rejection sampling maps the result to one of 219,000 equally likely tickets. Disjoint ticket intervals provide the exact probabilities above. No combinations are enumerated by the shipping app. The versioned `someday.draw.v1` encoding must remain stable in future updates; changing it would change existing users' results.

The enrollment timezone is retained, so traveling does not change a date's draw. The day advances at midnight in that timezone. Calendar arithmetic handles leap years and daylight-saving changes. This is an offline keepsake, not a tamper-proof lottery: changing device time, editing local data, or deliberately resetting an installation cannot be universally prevented without a trusted service. There are no prizes or purchasable chances.

The secret and authoritative eligible-day bitset live in a shared, non-synchronizing, device-only Keychain item. No draw key is written to the app container or exported. The app and widget serialize read/check/commit with a cross-process file lock. Storage errors fail closed: no automatic replacement identity.

Elapsed time comes from the public continuous monotonic clock, including device sleep. A detected reset or wall-clock discrepancy pauses draws for 24 continuous, stable-clock hours from detection. Only the resumption date is awarded; unverified gap dates are skipped. A fixed time anchor prevents accumulating small clock shifts. A persistent elapsed-time allowance also blocks repeat-quarantine/midnight draw amplification; a rate-limited day can wait longer instead of receiving an extra chance. Normal, verifiable same-session missed days are reconstructed.

Receipts use CryptoKit AES-GCM and an owner-derived HKDF key. Checking a receipt authenticates it against the current protected collection; it never imports an identity, rolls back state, or restores a lost Keychain. PNG cards are the portable keepsake option. See [SECURITY.md](SECURITY.md) for the threat model, reproduced attacks, limitations, and release gates.
Pixel glyphs are drawn with Canvas. The sole bundled bitmap is the original app icon, generated by `Tools/RenderIcon.swift`. Sharing renders a PNG only on demand and reuses one temporary output file. No animation loops, background services, remote assets, databases, telemetry, or networking code are included.

## Delivery and persistence limits

- Widget timelines contain only a verified current result and a neutral expiry entry. No future wins are computed or scheduled. iOS controls actual refresh and display timing.
- Optional local notifications are sent after the app or widget commits a newly checked current-day win. There is no daily background daemon, advance win schedule, or guaranteed alert while the app/widget never runs.
- Only verified eligible dates can enter the collection. A restart or clock change may cause missed dates to be skipped by design.
- Device erasure, Keychain loss, or changing signing identity can permanently lose the collection. Keychain retention after uninstall is not a guarantee. Receipts cannot recover a missing authority or transfer wins to a new phone.
- Offline anti-cheating is not independent proof. A modified executable, compromised OS, multiple devices, system-state rollback, and forged screenshots remain outside the guarantee.
- Old unsigned pre-release JSON saves are rejected and left untouched, not silently migrated or deleted.
- A sample card is clearly watermarked and is never added to the real collection.

## Development checks

```sh
make check
make previews
make icon
```

`make check` runs standalone core and adversarial security checks, validates Xcode project references and assets, checks property lists, and parses iOS Swift sources. It works with this Mac's Command Line Tools. `Tests/SomedayCoreTests` additionally contains XCTest tests for environments with full Xcode; run `swift test` there.

The standalone core checks cover all 219,000 ticket outcomes, a Python-verified HMAC golden vector, 100 years of in-range draws, per-installation differences, daily versus missed-day reconstruction, idempotency, clock rollback, DST, leap dates, timezone stability, authenticated receipt verification and storage growth. Security checks exercise clock jumps, gradual drift, reboot quarantine, replay, foreign identities, jackpot seed grinding, ciphertext bit flips, 2,000 malformed imports, and hostile file types.

`make previews` compiles the actual screen views with macOS SwiftUI and isolated development fixtures, then writes images to `Previews/`. These are iPhone-sized **design previews**, not iOS simulator captures. Preview tools and fixtures are excluded from both shipping targets.

On the development Mac used here, the core checks pass and the main views type-check against macOS SwiftUI. **An iOS SDK build, device interaction checks, widget installation, notifications, share-sheet behavior, accessibility testing on VoiceOver, release IPA size, and Instruments measurements still require full Xcode.** No measured IPA-size or launch-time claim is made yet.

## Source map

- `App/`: SwiftUI screens, app state, sharing, receipt verification, notifications.
- `Shared/`: original pixel glyphs, continuous clock, Keychain adapter, and cross-process storage transactions.
- `Sources/SomedayCore/`: calendar, odds, deterministic draws, protected authority, verification gate, and bounded imports.
- `Widget/`: WidgetKit provider and five widget families.
- `Config/`: identifiers, entitlements, Info plists, privacy manifest.
- `Tools/` and `Tests/`: development-only validation and artwork/preview generation.
